# External Baseline and Literature Policy

Merges the former `EXTERNAL_BASELINE_COMPARISON_POLICY.md` and `LITERATURE_NORMALIZATION_POLICY.md`.
Executed by study S71 (`studies/S71/`, `contracts/EXTERNAL_BASELINE_CONTRACT.yaml`).

## Evidence sources
Prior work may be used as an external baseline only when its provenance and comparability are explicit.

| Source class | Meaning | Metric status (`METRIC_PROVENANCE_CONTRACT`) |
|---|---|---|
| `LITERATURE_REPORTED` | copied/paraphrased from a cited source, exactly as reported | `LITERATURE_REPORTED` |
| `REPRODUCED` | our execution of the published method/artifact in our controlled environment | `REPRODUCED` |
| `OUR_MEASURED` | produced by our current method/baseline implementation | `MEASURED` / `TOOL_REPORTED` |
| `REFERENCE_ORACLE` | exhaustive or otherwise explicitly defended reference set | `REFERENCE_ORACLE` |

`OUR_MEASURED` is a comparison-table label only; the stored metric carries the canonical status in the last column.

## Comparability labels
Every comparison row carries exactly one label:

- `DIRECT` — every alignment field below matches.
- `CONTROLLED_RE_EVALUATION` — the external method was re-run by us under our aligned protocol.
- `INDIRECT_ONLY` — at least one material field differs and no controlled re-evaluation was done.
- `NOT_COMPARABLE` — the difference changes the scientific question; no numerical comparison is shown.

Alignment fields: benchmark/source revision; top function and input set; pragma/design space;
device/board/package/speed grade; HLS/RTL/implementation tool versions; clock constraints; correctness criteria;
objective/constraint definitions (including feasibility); evaluation stage; search/evaluation budget;
repetition/statistical protocol.

## Prohibited behaviour
- No filling missing paper values by inference.
- No treating a reported figure as if it were generated by our flow.
- No comparing different FPGA devices without an explicit caveat.
- No comparing HLS-only numbers to post-route numbers as the same metric.
- No comparing different feasibility definitions as identical.
- No mixing different tool versions without recording the difference.

## Reproduction hierarchy
1. Official artifact/code + official dataset.
2. Official code + compatible benchmark recreated from source.
3. Third-party implementation with explicit attribution.
4. Literature-only comparison.

The study must preserve the highest available level and report why a higher level was not possible.
